# 微信小游戏桌面自动化 · 作业手册

腾讯系小游戏跑在 `WeChatAppEx.exe` 宿主里，画面全是 canvas：UI 自动化树只有一个 document 加一堆无标签 image，**没有任何可读按钮**。所有交互只能「点击/探针脚本 → 像素判定状态」。

## 执行规则

1. **坐标一律是设计坐标（基准 1138×708），禁止把 Read 显示图上量出的像素直接当点击坐标**。显示的截图是缩放图（实测系数 ≈0.40）。唯一方法：显示图量值 ÷ 显示图尺寸 × 1138/708，或探针扫色块边界，或用档案已验证值；脚本运行时会自动换算到实时客户区。
2. **自动战斗开启唯一入口=`wxautoensure.ps1`（OCR 单判据，v1.1.12 起全链统一）**：读 autobtn 区 (175,158)-(275,195)（「取消自动」=ON /「自动战斗」=OFF，N=3 容错）→ OFF 点 (215,172)→重读验证；**ON 优先判定不误关**；UNKNOWN（转场黑屏）继续轮询；超时/点击超 3 次 FAIL→截图人工核对。与血量/白字 tip/按钮底色零关系（事件10/11，见 `incidents.md`）。同角色登录期间换图保持，切角色必重置。wxclick `auto`/`autonow` 步骤=内部委托 wxautoensure（FAIL 整体 exit 3，语义不变）；**旧模板匹配 gated 循环已退役**（布局常量/锚点被 v1.1.10/11 甩下），模板资产/wxautostate/wxprobe AUTO 态仅存诊断用途。
3. 「开启冥渊」点击后必须确认按钮文字已变「冥渊模式」。
4. 重登/重开后选中角色**重置为第1个**（事件5）；同会话再进选角页则停在「上次选中角色所在屏」（2026-10-27 实证）。选中态 OCR 判不了——选卡一律走 wxcharsel 幂等双击，勿再提金框验证（已退役，2026-10-27 用户定版：身份确认永久不做）。
5. 窗口遮挡：置顶面板脚本管不了，点左侧按钮前截图确认完整，被挡请用户清开。
6. 角色死亡弹「是否使用不死鸟羽毛」→ 点「立即复活」(722,516)（已授权）。

## 0. 运行环境（单机）

- **仅支持当前这台电脑**（用户 2026-10-26 定版：公司机/双机支持废止，公司代码与档案已删除；跨机器移植不在范围内）。
- 屏幕/DPI：2560×1440 @125%；坐标体系：设计坐标 1138×708 + 运行时等比换算（DPI-aware）。

- **客户区结构（2026-10-26 实测定版；权威表述唯一版本=coords.md 头部「坐标体系权威表述」+ _wxcommon.ps1 几何注释）**：`[微信内嵌标题栏 固定 55px，不随窗口缩放] + [游戏画布 等比缩放]`。几何层换算 `S=min(宽/1138, (高-55)/653)`，纵向 `screen_y = OY + 55 + (design_y-55)×S`——**基准 1138×708 时 S=1 与旧模型重合，所有档案坐标零失效；任意窗口尺寸（含非等比/缩小窗 0.40×）均可准确点按**。chrome 常量 `$WX_CHROME_H=55` 由 preflight 自动审计（wxcanvas.ps1 实测比对），不符即停机。**⚠️ 铁律（2026-10-27 23:0x）：换算严禁手算——正向 `ConvertTo-ScreenPoint`、反向 `ConvertFrom-ScreenPoint`，标定脚本同样必须调函数；wxshot `-Raw` 截图无量纲≠设计坐标（design_y=55+y/S）。**

## 1. 定位目标窗口

1. 一个游戏一个 `WeChatAppEx.exe` 进程，用窗口标题匹配：`Get-Process WeChatAppEx | Select Id,MainWindowTitle`，pid 传 `-Pid2`。
2. 报 `ERR: window not found` → 重查进程列表确认窗口标题还在。
3. URL 形如 `https://servicewechat.com/<appid>/<version>/page-frame.html`（勇士之心 appid `wx77d3595d9d76a623`）。

## 2. 坐标校准

本机用**设计坐标 1138×708**：档案/坐标表数字直接传入脚本，`_wxcommon` 按实时客户区等比换算（含居中留边），误差 ≤1px。**⚠️ Read 显示图是缩放图（≈0.40），显示图上的绝对数字严禁直接当点击坐标。** 截图（`wxshot` 锚定模式）已归一化到设计尺寸，图内像素可直接与坐标表对照。

## 3. 按钮热区偏移

点了没反应 → 按 +30~50px 下移再试。命中后固化进档案。连续两次不中 → 按专家熔断纪律处理，请用户帮忙，不盲点。

## 4. 点击规范（2026-10-27 用户裁定：防检测扰动体系整体删除）

~~时间与位置随机扰动~~（点击坐标偏移 ±J、随机停顿/按压时长）——用户裁定防第三方检测属多虑，**已全部删除**：点击一律精确落在设计坐标，随机 sleep 改固定值。
战斗等待不变：以 features 档案实测单场时长为准（`features/dungeon-runs.md`），**wxgrind 用探针轮询等结算（上限 90s）**。
点击落空元凶：过渡未就绪/坐标偏差（小热区按钮偏 1px 即失）/布局不符/前台丢失/弹窗遮挡（incidents.md）。

## 5. 状态判定与循环

**优先探针枚举，只在 UNKNOWN 时人工截图**——省 token 的关键。

| 画面特征 | 状态 |
|---|---|
| 按钮模板=「取消自动」(ON) | 已开启，别碰 |
| 按钮模板=「自动战斗」(OFF) | wxautoensure 点 (215,172) 开启 |
| 「再来一次」+「返回城镇」 | 结算页（两行 y≈331 / 三行 y≈389 浮动） |
| 血条 + 连击数 | 战斗中 |
| 点完仍在结算页/副本列表 | 次数或体力耗尽 |

标准循环：开自动一次 → 等一场时长 → 探针确认结算 → 点「再来一次」→ 确认进图 → 未进图即停。停止条件用**行为**判断（详见 §9 与 game-mechanics.md）。

## 7. 像素探针原理

结算按钮暗红：`R>100 且 R-B>50 且 22<G<78`；扫描带 BX=915、y 225~445，红块起始 y+20 为点击点（面板 Y 浮动 ±45px，禁写死）。自动战斗=按钮文字模板匹配（§执行规则2），模板绑定**设计尺寸 1138×708**——客户区同比例变化由运行时等比换算+截图归一化吸收，**不再需要重裁**；仅当同比例下持续 UNKNOWN（真实布局重排）才走 wxrecrop。改阈值前先 `wxautostate -Debug`/`-Img` 采样；按钮 RGB 实测数据见 `coords.md`。

## 8. 低延迟执行

「开始战斗→等加载→开自动」绝不拆成多次工具往返——进图后 5~10 秒最脆弱。用 wxclick `-Steps` 一次进程连点，聚焦只做一次。

| 场景 | 等待策略 |
|---|---|
| 进图后开自动 | 加载 3.5~4.5s 后立刻点 |
| 循环「再来一次」 | 间隔 1~2s |
| 一场战斗时长 | 以 features 档案实测时长为准（§4），首轮 +3~5s 兜底 |

## 11. 故障排查

| 症状 | 原因 | 处理 |
|---|---|---|
| 「在此系统上禁止运行脚本」 | WorkBuddy PowerShell 会话 Restricted | 子进程跑：`powershell -NoProfile -ExecutionPolicy Bypass -File <脚本> <参数>` |
| CopyFromScreen 报「句柄无效」 | 屏幕锁定/会话切走 | 停手；用户解锁后自愈，恢复后再核状态 |
| 截图是纯色 4~5KB | 锁屏/遮挡/最小化（事件14 复盘定论，非渲染假死） | wxprobe=OCCLUDED / wxshot WARN 已自动识别；解锁+wxrestore 后重截，仍异常停手问用户 |
| 点击落进用户其它窗口 | SetForegroundWindow 被前台锁拦截 | wxclick/wxpoke 已带前台守卫（拒点）；复现→停手 |
| 按钮模板全 UNKNOWN（dist 双高） | 按钮被遮挡/特效扫过/真实布局重排 | wxshot 人工核对；同比例尺寸下仍持续 UNKNOWN 才重裁模板（单纯尺寸变化已由换算吸收） |
| **OCR 任务区整区读空（raw=[]），页面内容目视正常** | **画布垂直居中漂移/区域边距过紧（事件21）** | 同图宽带扫描定位文字真实位置再重标区域；根治机制（CANVASTOP）见 coords.md 权威表述 |
| 脚本报 `ERR: client=… 长宽比/缩放系数不符` | 窗口被拉成非设计比例、过大过小或尺寸读取异常 | 跑 `wxresize.ps1` 复位（同比例任意尺寸均可，日常无需复位）；仍异常→停止问用户，不要改设计基准常量迁就窗口 |
| 点了没反应、光标不在预期位置 | delta 失效/窗口被移动 | 重新校准（读最新 origin） |
| 光标在按钮上没反应 | 热区偏移 | 下移 +30~50px 重试一次 |
| 首点无效之后正常 | 首点只激活窗口 | 先点标题栏聚焦 |
| 新量坐标点击全落空 | 显示图缩放陷阱 | 探针扫色块边界取真实坐标 |
| 探针全零但画面确有目标 | 用了缩放截图/扫描带不符 | PowerShell 物理截图；`-Debug` 重采样 |
| 窗口挪屏幕中间+跳重登 | 点了挂机弹窗「取消」 | 该弹窗必须点「确定」；重走登录流程 |
| **刷图中频繁死亡/被秒** | **自动战斗未开启（铁律第2条）** | **第一优先 wxcrop 核对按钮文字=「取消自动」；未开→立即点 (224,181) 并裁剪验证，再查其它原因。日常自动刷的图不存在开自动打不过** |
| `ERR: window not found` | 窗口被关/收回 | 重查 `Get-Process WeChatAppEx` 拿新 pid |
| 换模型/新会话首次执行自创方法踩坑 | 未读 references 档案 | 专家开局协议强制自检报告（事件18） |

## 12. 新增副本/任务的标准动作

1. 查 `coords.md`：有记录直接照跑；没有 → 截图定位入口，wxclick 连招进图，探针确认状态，坐标流程写入档案。
2. 用户原话的任务分配先写入 `tasks.md` 再执行。
3. 任务结束回报场次/体力/邀请函/金币，同步档案；踩坑按 `update-log.md` 路由。

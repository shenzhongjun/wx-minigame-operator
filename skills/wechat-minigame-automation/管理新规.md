# wechat-minigame-automation skill 管理新规（v2，2026-10-24）

> **定位**：本 skill 的**维护层文档**（宪法）。只管"知识怎么归档、文件怎么增长"，不含任何操作知识。
> 它**故意不占 SKILL.md 的 200 行预算**——上限只约束操作内容，维护规则放这里，两边互不挤压。
> **适用对象**：维护本 skill 的一切行为（操作员 agent 沉淀知识时、用户手动整理时）。
> 角色纪律（红线/熔断/开局协议/冒烟制）属于专家包 `wx-minigame-operator` 的 agent 定义，不在本文件管辖内。

## 一、文件分工（唯一权威源）

> **本表是文件分工的唯一权威定义**。SKILL.md 的"档案路由索引"只是执行视角的入口清单，agent.md 的"作业手册"节只是必读授权清单——两处内容与本表冲突时，以本表为准并修正之。

| 文件 | 内容 | 变更时机 |
|---|---|---|
| `SKILL.md` | **调度索引 + 跨版本稳定核心**：窗口机制、脚本清单、坐标体系、状态判定、通用排错表、指向各 references 的路由 | 仅机制变化时改 |
| `references/tasks.md` | **只放角色-副本任务档案与每日任务分配**，不放任何事件记录 | 任务一下达先写 |
| `references/game-mechanics.md` | 游戏数值与机制：消耗/刷新/免费首把/每日循环。**唯一数值源，流程文件禁止复述** | 用户定版或游戏更新时 |
| `references/update-log.md` | 踩坑/优化流水缓冲区，带三态路由（见第四节） | 每次踩坑/修复/优化时追加 |
| `references/incidents.md` | 事件根因档案：完整经过、根因、修复记录，长期保存 | 重大事故时建档 |
| `references/coords-*.md` | **纯标定数据**：坐标表、缩放换算、像素判定、探针校准、按钮判定源（流程已拆至 features/） | 标定新坐标时 |
| `references/features/*.md` | **功能模块**：每个自动化功能/操作流程一个文件（见第三节） | 新增/修改功能时 |
| `references/todo-scripts.md` | 待办清单 | 待办变化时 |

## 二、新知识落笔前三问

1. **会过时吗？** 游戏数值、用户临时安排 → `game-mechanics.md`；单次踩坑 → `update-log.md`；重大事故 → `incidents.md`。均禁止进 SKILL.md。
2. **只跟某台电脑/某个副本有关吗？** 是 → `coords-*.md`。
3. **是持久性教训吗？**（机制性行为：缩放陷阱、编码坑、执行策略等）→ SKILL.md 排错表**只加一行**"症状｜原因｜处理"，细节入 `incidents.md`。

## 三、增长管理：SKILL.md 是索引，不是仓库（防臃肿核心条款）

skill 会持续长出新的自动化功能、机制理解、坐标——**增长全部走"辐条"（references），SKILL.md（轮毂）只长索引行**：

| 增长类型 | 内容去哪 | SKILL.md 上的代价 |
|---|---|---|
| 新自动化功能 | **新建 `references/features/<功能名>.md`**，固定结构：目的｜触发条件｜执行步骤｜用到的脚本｜坐标引用｜停止条件｜排错 | 功能路由表**加一行**：`功能名｜触发场景｜详见 features/<文件>` |
| 新游戏机制 | `game-mechanics.md` | 0 行 |
| 新坐标 | `coords-*.md` | 0 行（脚本清单里已有指针） |
| 新脚本 | 脚本本体 | 脚本清单表**加一行** |
| 新坑 | `incidents.md` + 视情况稳定层 | 排错表**加一行**（或 0 行） |
| 新文件/新目录 | — | 文档结构表**加一行** |

**硬规则**：
- SKILL.md 正文段落**只允许改写，不允许追加**；一切新增内容以"表格加行"或"路由表加行"的形式进入；
- 每类增长在 SKILL.md 的预算就是**一行/一格**——装不下说明内容属于辐条文件，不属于自己的家；
- **180 行警戒线**：SKILL.md 达到 180 行时，维护动作优先于新增——找出可降级的内联段落（如已被 features 模块覆盖的旧流程叙述）迁入 references，腾出额度再收新内容；
- 上限 **200 行**，同一主题禁新旧两版并存，失效排错行及时删除。

## 四、update-log.md 三态路由

| 状态 | 判定 | 处置 |
|---|---|---|
| `已提升` | 教训是持久性的 | 当场写入稳定层（排错表/coords/game-mechanics/features），该行**立即删除** |
| `已修复` | 修复后不再可能复发 | 修复手段必须已落稳定层；保留至**下次同场景验证通过**，最长 5 天 |
| `待观察` | 拿不准 | 留 log 跟踪；**超 14 天 → 提请用户裁决** |

update-log 任何一行最终只有两种归宿：进了稳定层后删除，或经用户裁决。缓冲区不存长期知识。

## 五、机器校验

维护后运行 `scripts\wxdoclint-personal.ps1`：校验 SKILL.md 行数上限、路由完整性（每个 references 文件必须在 SKILL.md 中被提及）、并打印行数。退出码非 0 = 有违规，先修复再交付。

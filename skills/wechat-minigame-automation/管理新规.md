# wechat-minigame-automation skill 管理新规（v3，2026-10-29）

> **定位**：本 skill 的**维护层文档**（宪法）。只管"知识怎么归档、文件怎么增长"，不含任何操作知识。
> 它**故意不占 SKILL.md 的 200 行预算**——上限只约束操作内容，维护规则放这里，两边互不挤压。
> **适用对象**：维护本 skill 的一切行为（操作员 agent 沉淀知识时、用户手动整理时）。
> 角色纪律（红线/熔断/开局协议/冒烟制）属于专家包 `wx-minigame-operator` 的 agent 定义，不在本文件管辖内。

## 一、文件分工与唯一入口（防双源漂移）

**本表是文件分工的唯一权威定义**。SKILL.md 的"档案路由索引"只是执行视角的入口清单，agent.md 的"作业手册"节只是必读授权清单——两处内容与本表冲突时，以本表为准并修正之。

每类事实只准一个家；其它文件出现同类内容**只准指针形式**（"见 xxx.md 对应行"），严禁复述。该是哪个文件就入哪个文件：

| 文件 | 管什么（唯一入口） |
|---|---|
| `SKILL.md` | 调度索引 + 跨版本稳定核心：窗口机制、脚本清单、坐标体系、状态判定、通用排错表、指向各 references 的路由；**上限 200 行** |
| `references/tasks.md` | 角色-副本任务档案、每日任务分配、当前任务（任务一下达先写） |
| `references/game-mechanics.md` | 游戏数值与机制：消耗/刷新/免费首把/每日循环/结算落点语义。**只收游戏机制，不收用户临时安排**（任务安排一律进 tasks.md） |
| `references/incidents.md` | 事件根因档案（索引版：每事件一行，完整原文见 git 历史） |
| `references/coords.md` | 坐标/OCR 区域/像素判据/点击锚点/缩放换算/探针校准（纯标定数据）；游戏标识（appid/区服/版本）在头部 |
| `references/features/*.md` | 自动化功能/操作流程，每个功能一个文件（目的｜触发｜步骤｜脚本｜坐标引用｜停止条件｜排错） |
| `references/run-environment-pitfalls.md` | 运行环境坑全集：执行方式/编码语法/输出捕获/桌面窗口（只收仍会复现的坑，注意时效） |
| `scripts/wxocr.ps1` 任务表 | OCR 任务定义（区域/kw/minhit；coords.md 留标定映射行） |
| `CHANGELOG.md` | 发版事实与详录 |

> 例外约定：历史档案（incidents/tasks 已归档节）**不改史**；作废警示行（删除线/「已作废」标注）允许保留旧值防反弹；脚本头注注释属文档的一部分，改档案时同步核对。

## 二、新知识落笔原则

**该是哪个文档就入哪个文档（见 §一表）；不确定归哪 → 停下来问用户。**

- 已有唯一归属档案的事实，只更新该档案 + 其余出现处改指针，**严禁新起炉灶复述**；
- 用户临时安排不进 game-mechanics（那只是游戏机制），任务安排一律进 tasks.md；
- 脚本头注里的旧注释随档案改动一并核对，发现过时表述顺带修订。

## 三、增长管理

一句话：**各文档只长自己的内容，SKILL.md 是索引不是仓库**——新内容一律进 references 辐条文件（新功能 → `features/<功能名>.md`，SKILL.md 功能路由表加一行），SKILL.md 只以表格加行/路由行吸收，上限 200 行，失效排错行及时删除，同一主题禁新旧两版并存。

## 四、机器校验

维护后运行 `scripts\wxdoclint.ps1`：校验 SKILL.md 行数上限、路由完整性（每个 references 文件必须在 SKILL.md 中被提及）、并打印行数。退出码非 0 = 有违规，先修复再交付。

## 五、发版引用扫描（发版 checklist 固定步骤）

改动任何坐标/阈值/机制值/时间规则后、commit 前：
1. 从本次 CHANGELOG 条目提取所有变更的数值关键词（旧值与新值）；
2. 全包 grep 旧值——命中处逐一改为指针或新值（含**脚本头注注释**）；
3. wxdoclint 过检后才准 commit。过时值残留（SKILL.md 旧锚点、daily-claim 12:00 等）均系跳过此步所致。

## 二、新知识落笔前四问（2026-10-28 三问增补第四问）

1. **会过时吗？** 游戏数值、用户临时安排 → `game-mechanics.md`；单次踩坑 → 视性质入 `run-environment-pitfalls.md`（环境类）或 `incidents.md`（事故类）加索引行；均禁止进 SKILL.md。
2. **只跟某台电脑/某个副本有关吗？** 是 → `coords-*.md`。
3. **是持久性教训吗？**（机制性行为：缩放陷阱、编码坑、执行策略等）→ SKILL.md 排错表**只加一行**"症状｜原因｜处理"，细节入 `incidents.md`。
4. **已有唯一归属档案吗？**（一之二白名单）有 → 更新该档案 + 其余出现处改指针，**严禁新起炉灶复述**。

## 之二、发版引用扫描（2026-10-28 用户定版，发版 checklist 固定步骤）

改动任何坐标/阈值/机制值/时间规则后、commit 前：
1. 从本次 CHANGELOG 条目提取所有变更的数值关键词（旧值与新值）；
2. 全包 grep 旧值——命中处逐一改为指针或新值（含**脚本头注注释**）；
3. wxdoclint 过检后才准 commit。过时值残留（SKILL.md 旧锚点、daily-claim 12:00 等）均系跳过此步所致。

## 三、增长管理：SKILL.md 是索引，不是仓库（防臃肿核心条款）

skill 会持续长出新的自动化功能、机制理解、坐标——**增长全部走"辐条"（references），SKILL.md（轮毂）只长索引行**：

| 增长类型 | 内容去哪 | SKILL.md 上的代价 |
|---|---|---|
| 新自动化功能 | **新建 `references/features/<功能名>.md`**，固定结构：目的｜触发条件｜执行步骤｜用到的脚本｜坐标引用｜停止条件｜排错 | 功能路由表**加一行**：`功能名｜触发场景｜详见 features/<文件>` |
| 新游戏机制 | `game-mechanics.md` | 0 行 |
| 新坐标 | `coords-*.md` | 0 行（脚本清单里已有指针） |
| 新脚本 | 脚本本体 | 脚本清单表**加一行** |
| 新坑 | `incidents.md` + 视情况稳定层 | 排错表**加一行**（或 0 行） |
| 新文件/新目录 | — | 文档结构表**加一行** |

**硬规则**：
- SKILL.md 正文段落**只允许改写，不允许追加**；一切新增内容以"表格加行"或"路由表加行"的形式进入；
- 每类增长在 SKILL.md 的预算就是**一行/一格**——装不下说明内容属于辐条文件，不属于自己的家；
- **180 行警戒线**：SKILL.md 达到 180 行时，维护动作优先于新增——找出可降级的内联段落（如已被 features 模块覆盖的旧流程叙述）迁入 references，腾出额度再收新内容；
- 上限 **200 行**，同一主题禁新旧两版并存，失效排错行及时删除。
